分類モデルが出力する確信度スコアは、しばしば「確率」としてそのまま扱われる。しかしその数値は本当に確率と呼べるのか。本記事では、ロジットからソフトマックスへの変換の仕組みと**キャリブレーション（較正）**という評価軸を整理したうえで、**Encoder（BERT系）と Decoder（GPT系 LLM）とで確信度の由来と信頼性がどう違うのか**を、数式で見ていく。

## 確信度はどこから来るのか — ロジットとソフトマックス

ニューラル分類モデルの最終層は、各クラスに対応する実数値スコア、いわゆる**ロジット（logit）** $$z \in \mathbb{R}^C$$（$$C$$ はクラス数）を出力する。ロジットは任意の実数で、それ自体に確率としての意味はない。これを確率のような形に変換するのがソフトマックス関数である。

$$
p_i = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}
$$

$$T$$ は温度パラメータで、学習時は通常 $$T = 1$$。$$T$$ を大きくすると分布は平坦（自信がないよう）に、小さくすると尖った（過信気味な）分布になる。

![ロジットからソフトマックスへの変換。相対スコアの順位と差は保存されるが、頻度としての正しさは保証されない]({{ '/assets/img/logits-softmax.svg' | relative_url }})

*ソフトマックスは相対スコアを確率単体に射影する変換にすぎない。$$z$$ 全体に定数を足しても $$p$$ は不変（平行移動不変性）であり、$$p$$ はロジットの「差」だけで決まる。*

ソフトマックスがやっていることは本質的に2つだけだ。**①指数関数で全スコアを正に変換し、②合計が1になるよう正規化する。**出力は「足すと1になる非負の数の組」なので確率の形式的な要件は満たすが、それは数学的な体裁であって、頻度としての意味が自動的に備わるわけではない。

ではなぜ「確率」と呼ばれるのか。クロスエントロピー損失（負の対数尤度）で学習した場合、モデルの出力は理論上**条件付き分布 $$P(y \mid x)$$ の推定量**になる。無限のデータと十分な表現力、完璧な最適化のもとでは、ソフトマックス出力は真の条件付き確率に収束する。つまり「確率」という解釈には理論的な裏付けが**ある**。問題は、現実の学習がこの理想条件をまったく満たさないことだ。有限のデータ、過剰なパラメータ、早期終了や正則化、そして学習分布と運用分布のズレ。これらすべてが、出力を真の確率から乖離させる。

## 「確率」と呼べる条件 — キャリブレーション

確信度が信用できるかどうかを測る概念が**キャリブレーション（較正）**である。定義はシンプルで、「確信度 0.9 と言った予測を集めたとき、そのうち実際に約 90% が正解している」状態を well-calibrated と呼ぶ。

$$
P(\hat{y} = y \mid \mathrm{conf} = p) = p \quad \text{for all } p \in [0, 1]
$$

これを可視化したのが**信頼度ダイアグラム（reliability diagram）**だ。確信度をビンに区切り、各ビンの平均確信度と実際の正解率をプロットする。対角線に乗れば理想、対角線より下に落ちれば「過信（overconfident）」である。ビンごとの gap を重み付き平均したものが **ECE（Expected Calibration Error）**で、代表的なキャリブレーション指標として使われる。

![信頼度ダイアグラム。過信したモデルの曲線は対角線より下に沈む]({{ '/assets/img/reliability-diagram.svg' | relative_url }})

*信頼度ダイアグラム。「確信度 0.95」の予測群の実際の正解率が 0.82 しかない、というのが典型的な過信パターン。*

重要な経験的事実として、**現代の深いニューラルネットワークは系統的に過信する傾向がある**（Guo et al., 2017）。同研究は、モデルの大規模化・深層化とともにキャリブレーションが悪化すること、そして検証セットで温度 $$T$$ を1つ学習するだけの**温度スケーリング（temperature scaling）**が驚くほど有効な補正になることを示した。

なお、キャリブレーションは**精度とは独立の性質**である。精度 99% でも常に「確信度 100%」を出すモデルは較正が悪く、精度 60% でも確信度が正直なモデルは較正が良い。「当たるか」と「自信の申告が正直か」は別の軸だ。

## Encoder の確信度（BERT系）

BERT・RoBERTa・DeBERTa に代表される Encoder モデルでの分類は、構造が明快だ。入力全体を双方向に読み込み、`[CLS]` トークン（あるいはプーリングした表現）の上に**分類ヘッド（線形層）**を載せる。出力次元はクラス数 $$C$$ と同じで、そこにソフトマックスをかける。

- **ラベル空間が閉じている。**出力は必ず $$C$$ 個のロジットで、確率は $$C$$ 個の候補に対する分配として一貫して定義される。
- **タスク専用に最適化されている。**分類ヘッドはそのタスクのクロスエントロピーだけで学習されるため、確信度は訓練分布を直接反映する。
- **出力の解釈が安定している。**同じ入力なら決定的に同じ確率が出る。プロンプトの書き方や出力形式のゆらぎといった問題は存在しない。

構造が素直なぶん、弱点もよく特徴づけられている。第一に、**ファインチューニング後のモデルは過信しやすい**。事前学習済みモデルを少量データで数エポック調整すると、訓練データをほぼ完全に記憶し、ロジットの差が極端に開く。結果として確信度が 0.99 付近に張り付く「確信度の飽和」が起きやすい（Desai & Durrett, 2020）。

第二に、**分布外（OOD）入力に対して「分からない」と言えない**。ソフトマックスは合計1への正規化を強制するため、訓練分布から外れた入力——たとえば感情分類モデルに法律文書を入れた場合——でも、どれかのクラスに高い確信度を割り当ててしまうことが多い。「どのクラスでもない」という逃げ道が構造上存在しない。

幸い、Encoder の確信度は**補正しやすい**。ラベル空間が固定で検証セットが作りやすいため、温度スケーリングや Platt スケーリング、isotonic regression といった事後較正がそのまま適用できる。

```python
# 温度スケーリングの最小実装（PyTorch）
# 検証セットのロジットとラベルで T を1変数最適化する
import torch

def fit_temperature(logits_val, labels_val):
    T = torch.nn.Parameter(torch.ones(1) * 1.5)
    opt = torch.optim.LBFGS([T], lr=0.01, max_iter=50)
    nll = torch.nn.CrossEntropyLoss()

    def step():
        opt.zero_grad()
        loss = nll(logits_val / T, labels_val)
        loss.backward()
        return loss

    opt.step(step)
    return T.item()   # 推論時: softmax(logits / T)
```

$$T > 1$$ が学習されれば「このモデルは過信していたので分布を平坦化する」という補正になる。$$T$$ は予測の順位を変えないため、精度には一切影響せず確信度だけを較正できる。

## Decoder の確信度（GPT系 LLM）

GPT 系の Decoder モデルで分類を行う場合、事情は根本的に変わる。Decoder に「分類ヘッド」はない。あるのは**次トークン予測**だけだ。分類は「プロンプトの続きとしてラベルを生成させる」タスクに翻訳される。このとき確信度の取り出し方は大きく2系統ある。

### ① トークン確率（logprob）を読む

プロンプトの次に来るトークンの分布から、ラベルに対応するトークンの確率を読み取る方法。理屈上は Encoder のソフトマックスに最も近いが、固有の問題がいくつもある。

- **語彙全体との競合。**Encoder の確率は $$C$$ クラスへの分配だが、Decoder の確率は語彙 $$V$$（数万〜数十万トークン）全体への分配である。ラベルトークンの確率は「はい」「答えは」のような無関係な続きにも食われる。ラベル候補だけを取り出して再正規化する処理が実質必須になる。
- **表面形の競合（surface form competition）。**同じ意味のラベルが「positive」「Positive」「ポジティブ」など複数の表記に分裂し、確率がそれらに割れる（Holtzman et al., 2021）。表記のバリエーションが多い概念ほど不利になるバイアスが生じる。
- **複数トークン問題。**ラベルが1トークンで表せない場合、系列全体の確率（各トークンの条件付き確率の積）を計算する必要があり、長いラベルほど確率が低く出る長さバイアスがかかる。
- **プロンプト感度。**few-shot 例の順番や言い回しを変えるだけで確率分布が大きく動く。Encoder には存在しなかった不安定性である。

### ② 言語化された自信（verbalized confidence）を出させる

「答えと、その自信を 0〜100% で述べよ」と指示して、モデル自身に数値を**言わせる**方法。logprob が取れない API でも使える手軽さから広く使われるが、この数値は**内部の確率計算の読み出しではなく、「自信を報告する文章」の生成**である点に注意が必要だ。経験的には、正解・不正解にかかわらず 80〜95% あたりの値に張り付く強い過信バイアスが繰り返し報告されている（Xiong et al., 2023）。

### RLHF はキャリブレーションを壊す

もう一つ、Decoder 特有の重要な現象がある。**事前学習直後のベースモデルは意外なほどよく較正されているのに、RLHF を施すとキャリブレーションが劣化する**というものだ。GPT-4 のテクニカルレポートには、事前学習済みモデルでは選択肢確率がほぼ対角線に乗るのに、RLHF 後は較正が大きく崩れる比較が示されている。人間に好まれる「歯切れのよい断定的な応答」への最適化が、確率分布を尖らせる方向に働くためと解釈されている。つまり、**チャット用に調整された LLM ほど、その確信度は額面通りに受け取れない**。

## どこまで信用してよいか

結論から言えば、確信度は**「較正して、順位情報として使う」ぶんには非常に有用**で、**「生の数値を確率として意思決定に直結させる」のは危険**、というのが妥当な線引きだ。

信用してよい使い方:

- **順位付け・トリアージ。**較正が崩れていても、確信度の**順序**は比較的保たれることが多い。「確信度の低い順に人間がレビューする」選択的予測（selective prediction）の運用は、生の値が歪んでいても機能する。
- **事後較正とセットでの閾値運用。**検証セットで信頼度ダイアグラムと ECE を確認し、温度スケーリング等で補正した上で「確信度 0.9 以上は自動処理、それ未満は人間へ」といった閾値を引く。閾値の意味は較正後にはじめて成立する。
- **同一分布内での相対比較。**同じモデル・同じ入力分布の中でのサンプル間比較は、分布シフトをまたぐ比較よりはるかに信頼できる。

信用してはいけない使い方:

- **未較正の値をリスク計算に使う。**「確信度 0.94 だから誤り率 6%」という読み替えは、較正を検証していない限り根拠がない。
- **OOD 検知の代用。**高い確信度は「入力が訓練分布内である」ことを意味しない。分布外入力ほど自信満々に間違うケースは頻繁に起きる。
- **モデル間・プロンプト間の確信度比較。**特に LLM では、プロンプトを一語変えただけで分布が動く。異なる設定間で確信度の絶対値を比べることに意味はほぼない。
- **verbalized confidence をそのまま信じる。**言語化された自信は補助信号にとどめ、可能なら logprob ベースの指標や、複数回サンプリングの一致率（self-consistency）と併用する。

## Encoder / Decoder の整理

| 観点 | Encoder（BERT系 + 分類ヘッド） | Decoder（GPT系 LLM） |
| --- | --- | --- |
| 確率の出どころ | 分類ヘッドのロジット → C クラスへのソフトマックス | 次トークン予測 → 語彙全体の分布からラベルを読む、または自信を言語化 |
| ラベル空間 | 閉じている（クラス数で固定） | 開いている（語彙全体と競合。再正規化が必要） |
| 出力の安定性 | 決定的で安定 | プロンプト・few-shot 順序・表記ゆれに敏感 |
| 典型的な歪み | 少量データでの FT による過信・確信度の飽和 | 表面形競合・長さバイアス・RLHF による較正劣化 |
| 較正のしやすさ | 高い。温度スケーリング等が直接効く | 工夫が必要。候補への再正規化＋温度、self-consistency などを併用 |
| 向いている場面 | ラベル固定・訓練データあり・閾値運用したい | ラベルが流動的・少数事例。確信度は補助信号にとどめる |

最後にひとことで要約するなら——**ソフトマックスの出力は「確率のかたちをした相対スコア」であり、確率として扱ってよいかどうかは、較正を検証してはじめて判断できる。**Encoder ではその検証と補正が素直に行え、Decoder では確率の取り出し自体に複数の落とし穴がある。どちらの場合も、まず自分のデータで信頼度ダイアグラムを一枚描いてみることが、その数値を信用してよいか確かめる一番の近道だ。
