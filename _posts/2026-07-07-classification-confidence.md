分類モデルが出力する確信度スコアは、そのまま「確率」として扱われることが多い。しかし、その数値を確率と呼んでよいかどうかは、確認しないと分からない。この記事では、logit から softmax への変換の仕組みと、calibration（較正）という評価軸を整理する。そのうえで、Encoder（BERT系）と Decoder（GPT系 LLM）とで確信度の由来と信頼性がどう違うのかを、数式で見ていく。

## 確信度の出どころ：logit と softmax

ニューラル分類モデルの最終層は、各クラスに対応する実数値のスコアを出力する。これを logit と呼び、$$z \in \mathbb{R}^C$$（$$C$$ はクラス数）と書く。logit は任意の実数で、それ自体に確率としての意味はない。これを確率の形に変換するのが softmax 関数になる。

$$
p_i = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}
$$

$$T$$ は温度パラメータで、学習時は通常 $$T = 1$$ とする。$$T$$ を大きくすると分布は平坦に（自信がない方向に）なり、小さくすると尖った（過信気味の）分布になる。

  <figcaption>softmax は、相対スコアを確率単体に射影する変換にあたる。\(z\) 全体に定数を足しても \(p\) は変わらず（平行移動不変性）、\(p\) は logit の「差」だけで決まる。</figcaption>
</figure>

softmax が行うのは、指数関数ですべてのスコアを正の値に変換することと、合計が1になるように正規化することの2つに限られる。出力は「足すと1になる非負の数の組」なので、確率の形式的な要件は満たす。ただし、それは形式の話で、頻度としての意味が自動的に備わるわけではない。

それでも「確率」と呼ばれるのには理由がある。cross-entropy 損失（負の対数尤度）で学習した場合、モデルの出力は理論上、条件付き分布 $$P(y \mid x)$$ の推定量になる。無限のデータ、十分な表現力、完璧な最適化がそろえば、softmax 出力は真の条件付き確率に収束する。「確率」という解釈には、この理論的な裏付けがある。しかし、現実の学習はこの理想条件を満たさない。データは有限で、パラメータは過剰で、早期終了や正則化が入り、学習分布と運用分布もずれる。これらが重なって、出力は真の確率から離れていく。

## 「確率」と呼べる条件：calibration

確信度が信用できるかどうかを測る概念を、calibration（較正）と呼ぶ。「確信度0.9と言った予測を集めたとき、そのうち実際に約90%が正解している」状態を well-calibrated と呼ぶ。

$$
P(\hat{y} = y \mid \mathrm{conf} = p) = p \quad \text{for all } p \in [0, 1]
$$

これを可視化したものが信頼度ダイアグラム（reliability diagram）で、確信度をビンに区切り、各ビンの平均確信度と実際の正解率をプロットする。点が対角線に乗れば理想的で、対角線より下に落ちれば「過信（overconfident）」を表す。ビンごとの差を重み付き平均したものは ECE（Expected Calibration Error）と呼ばれ、代表的な calibration 指標として使われる。

  <figcaption>信頼度ダイアグラム。「確信度0.95」の予測群の実際の正解率が0.82しかない、というのが典型的な過信のパターンになる。</figcaption>
</figure>

現代の深いニューラルネットワークには、系統的に過信する傾向がある（Guo et al., 2017）。この研究は、モデルが大きく深くなるほど calibration が悪化することを示した。また、検証セットで温度 $$T$$ を1つ学習するだけの温度スケーリング（temperature scaling）が、補正として有効なことも示している。

calibration は、精度とは独立の性質を持つ。精度99%でも常に「確信度100%」を出すモデルは較正が悪く、精度60%でも確信度が実際の正解率と合っているモデルは較正が良い。「当たるか」と「自信の申告が正確か」は、別の軸として扱う。

## Encoder の確信度（BERT系）

BERT・RoBERTa・DeBERTa に代表される Encoder モデルでの分類は、構造が単純になっている。入力全体を双方向に読み込み、`[CLS]` トークン（またはプーリングした表現）の上に分類ヘッド（線形層）を載せる。出力次元はクラス数 $$C$$ と同じで、そこに softmax をかける。この構造には次の特徴がある。

- ラベル空間が閉じている。出力は必ず $$C$$ 個の logit で、確率は $$C$$ 個の候補への分配として一貫して定義される。
- タスク専用に最適化されている。分類ヘッドはそのタスクの cross-entropy だけで学習されるので、確信度は訓練分布を直接反映する。
- 出力の解釈が安定している。同じ入力からは必ず同じ確率が出る。プロンプトの書き方や出力形式のゆらぎといった問題は起きない。

この構造には弱点が2つある。まず、fine-tuning 後のモデルは過信しやすい。事前学習済みモデルを少量データで数エポック調整すると、訓練データをほぼ完全に記憶し、logit の差が極端に開く。その結果、確信度が0.99付近に張り付く「確信度の飽和」が起きやすい（Desai & Durrett, 2020）。

次に、分布外（OOD）の入力に対して「分からない」と言えない。softmax は合計が1になるように正規化するので、感情分類モデルに法律文書を入れた場合のように訓練分布から外れた入力でも、どれかのクラスに高い確信度を割り当てることが多い。「どのクラスでもない」という出力は、構造上できない。

一方で、Encoder の確信度は補正しやすい。ラベル空間が固定で検証セットも作りやすいので、温度スケーリング、Platt スケーリング、isotonic regression といった事後較正をそのまま適用できる。

```python
# 温度スケーリングの最小実装（PyTorch）
# 検証セットの logit とラベルで T を1変数最適化する
import torch

def fit_temperature(logits_val, labels_val):
    T = torch.nn.Parameter(torch.ones(1) * 1.5)
    opt = torch.optim.LBFGS([T], lr=0.01, max_iter=50)
    nll = torch.nn.CrossEntropyLoss()

    def step():
        opt.zero_grad()
        loss = nll(logits_val / T, labels_val)
        loss.backward()
        return loss

    opt.step(step)
    return T.item()   # 推論時: softmax(logits / T)
```

$$T > 1$$ が学習された場合は、モデルが過信していたので分布を平坦にする、という補正になる。$$T$$ は予測の順位を変えないので、精度に影響を与えずに確信度だけを較正できる。

## Decoder の確信度（GPT系 LLM）

GPT 系の Decoder モデルで分類を行う場合は、事情が大きく変わる。Decoder には分類ヘッドがなく、あるのは次トークン予測だけなので、分類は「プロンプトの続きとしてラベルを生成させる」タスクに置き換えられる。このとき、確信度の取り出し方は大きく2つに分かれる。

### 1. トークン確率（logprob）を読む

プロンプトの次に来るトークンの分布から、ラベルに対応するトークンの確率を読み取る。理屈のうえでは Encoder の softmax に最も近いが、固有の問題がいくつかある。

- 語彙全体と競合する。Encoder の確率は $$C$$ クラスへの分配だが、Decoder の確率は語彙 $$V$$（数万〜数十万トークン）全体への分配になる。ラベルトークンの確率は、「はい」「答えは」のような無関係な続きにも取られる。そのため、ラベル候補だけを取り出して再正規化する処理が実質的に必須になる。
- 表面形が競合する（surface form competition）。同じ意味のラベルが「positive」「Positive」「ポジティブ」など複数の表記に分かれ、確率もそれらに分散する（Holtzman et al., 2021）。表記のバリエーションが多い概念ほど不利になる。
- ラベルが複数トークンになる。ラベルを1トークンで表せない場合は、系列全体の確率（各トークンの条件付き確率の積）を計算する必要があり、長いラベルほど確率が低く出る。
- プロンプトに敏感に反応する。few-shot 例の順番や言い回しを変えるだけで、確率分布が大きく動く。Encoder にはなかった不安定性にあたる。

### 2. 言語化された自信（verbalized confidence）を出させる

「答えと、その自信を0〜100%で述べよ」と指示して、モデル自身に数値を言わせる。logprob が取れない API でも使えるので、広く使われている。ただし、この数値は内部の確率計算を読み出したものではなく、「自信を報告する文章」として生成されたものなので、注意が必要になる。正解・不正解にかかわらず80〜95%あたりの値に集まる強い過信バイアスが、繰り返し報告されている（Xiong et al., 2023）。

### RLHF は calibration を壊す

Decoder には、もう1つ特有の現象がある。事前学習直後のベースモデルはよく較正されているのに、RLHF を施すと calibration が劣化する。GPT-4 のテクニカルレポートには、事前学習済みモデルでは選択肢の確率がほぼ対角線に乗るのに対し、RLHF 後は較正が大きく崩れる、という比較が示されている。人間に好まれる断定的な応答への最適化が、確率分布を尖らせる方向に働くためだと解釈されている。チャット用に調整された LLM ほど、確信度を額面どおりには受け取れない。

## どこまで信用してよいか

確信度は、較正したうえで順位の情報として使うなら有用で、生の数値を確率としてそのまま意思決定に使うのは危険、と考えるのが妥当な線引きになる。

次の使い方は信用してよい。

- 順位付けやトリアージに使う。較正が崩れていても、確信度の順序は比較的保たれることが多い。「確信度の低い順に人間がレビューする」という選択的予測（selective prediction）の運用は、生の値が歪んでいても機能する。
- 事後較正と組み合わせて閾値を決める。検証セットで信頼度ダイアグラムと ECE を確認し、温度スケーリングなどで補正したうえで、「確信度0.9以上は自動処理、それ未満は人間へ」といった閾値を置く。閾値が意味を持つのは、較正したあとになる。
- 同じ分布の中で相対的に比べる。同じモデル、同じ入力分布の中でのサンプル間の比較は、分布シフトをまたぐ比較よりずっと信頼できる。

次の使い方は避ける。

- 未較正の値をリスク計算に使う。「確信度0.94だから誤り率6%」という読み替えは、較正を検証していない限り根拠がない。
- OOD 検知の代わりに使う。確信度が高くても、入力が訓練分布内にあるとは限らない。分布外の入力に対して高い確信度で間違えることは、頻繁に起きる。
- モデル間やプロンプト間で確信度を比べる。とくに LLM では、プロンプトを1語変えただけで分布が動く。異なる設定の間で確信度の絶対値を比べても、ほとんど意味がない。
- verbalized confidence をそのまま信じる。言語化された自信は補助的な信号として扱い、可能なら logprob ベースの指標や、複数回サンプリングしたときの一致率（self-consistency）と併用する。

## Encoder / Decoder の整理

| 観点 | Encoder（BERT系 + 分類ヘッド） | Decoder（GPT系 LLM） |
| --- | --- | --- |
| 確率の出どころ | 分類ヘッドの logit → C クラスへの softmax | 次トークン予測 → 語彙全体の分布からラベルを読む、または自信を言語化 |
| ラベル空間 | 閉じている（クラス数で固定） | 開いている（語彙全体と競合。再正規化が必要） |
| 出力の安定性 | 決定的で安定 | プロンプト・few-shot 順序・表記ゆれに敏感 |
| 典型的な歪み | 少量データでの FT による過信・確信度の飽和 | 表面形競合・長さバイアス・RLHF による較正劣化 |
| 較正のしやすさ | 高い。温度スケーリング等が直接効く | 工夫が必要。候補への再正規化＋温度、self-consistency などを併用 |
| 向いている場面 | ラベル固定・訓練データあり・閾値運用したい | ラベルが流動的・少数事例。確信度は補助信号にとどめる |

softmax の出力は確率の形をした相対スコアで、確率として扱ってよいかどうかは、較正を検証して初めて判断できる。Encoder ではその検証と補正を行いやすく、Decoder では確率の取り出し方自体に注意点が多い。どちらの場合も、まず自分のデータで信頼度ダイアグラムを描いて確かめるのがよい。
